## **API2 — Importing Database Structures**

The import API creates API2 table structures from **PostgreSQL SQL**, **DBML**, or **API2 JSON**. Imports require an authenticated user and are processed through the same structure-creation jobs used by the structure API.

### **Endpoints**

| Method | Path | Description |
|---|---|---|
| POST | `/api/v1/import/sql` | Import PostgreSQL `CREATE TABLE` statements |
| POST | `/api/v1/import/dbml` | Import a DBML schema |
| POST | `/api/v1/import/json` | Import tables in API2's JSON structure format |
| GET | `/api/v1/import/dbml` | Download the built-in DBML example |
| GET | `/api/v1/import/json` | Get the JSON Schema used to validate JSON imports |

All import requests require a bearer token:

```http
Authorization: Bearer <token>
```

Imports are intended for table structures. SQL statements or JSON data representing rows are not inserted as records.

### **Import SQL**

Send PostgreSQL `CREATE TABLE` statements in the `sql` property:

```bash
curl -X POST "http://localhost:4000/api/v1/import/sql" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  --data-binary @- <<'JSON'
{
  "sql": "CREATE TABLE customers (\n  id uuid NOT NULL,\n  name varchar(255) NOT NULL UNIQUE\n);\n\nCREATE TABLE orders (\n  id uuid NOT NULL,\n  customer_id uuid NOT NULL,\n  total numeric(10,2) NOT NULL,\n  CONSTRAINT orders_customer_fk\n    FOREIGN KEY (customer_id) REFERENCES customers(id)\n);"
}
JSON
```

The same import can be uploaded as a file using `multipart/form-data`:

```bash
curl -X POST "http://localhost:4000/api/v1/import/sql" \
  -H "Authorization: Bearer <token>" \
  -F "file=@schema.sql"
```

The SQL parser processes PostgreSQL `CREATE TABLE` statements. It imports columns, supported PostgreSQL types, `NOT NULL`, `UNIQUE`, defaults, inline references, and table-level foreign keys. Other statement types are ignored.

Successful response:

```json
{
  "data": "Import successful"
}
```

### **Import DBML**

Send DBML source in the `dbml` property. Define referenced tables before the tables that depend on them:

```bash
curl -X POST "http://localhost:4000/api/v1/import/dbml" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  --data-binary @- <<'JSON'
{
  "dbml": "Table customers {\n  id uuid [not null, pk]\n  name varchar [not null, unique]\n}\n\nTable orders {\n  id uuid [not null, pk]\n  customer_id uuid [not null]\n  total decimal [not null]\n}\n\nRef: orders_customer orders.customer_id > customers.id"
}
JSON
```

Successful response:

```json
{
  "data": [
    {
      "table": "customers",
      "message": "table imported",
      "error": false
    },
    {
      "table": "orders",
      "message": "table imported",
      "error": false
    }
  ]
}
```

Use `GET /api/v1/import/dbml` to download the server's built-in DBML example:

```bash
curl "http://localhost:4000/api/v1/import/dbml" \
  -H "Authorization: Bearer <token>" \
  -o api2-schema.dbml
```

### **Import JSON**

JSON imports use the same structure format generated by the DBML parser. The request may contain a `tables` array:

```bash
curl -X POST "http://localhost:4000/api/v1/import/json" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  --data-binary @- <<'JSON'
{
  "tables": [
    {
      "name": "customers",
      "parent": "base",
      "schema": [
        {
          "name": "name",
          "type": "varchar",
          "options": {
            "required": true,
            "unique": true
          }
        }
      ]
    },
    {
      "name": "orders",
      "parent": "base",
      "schema": [
        {
          "name": "customer_id",
          "type": "uuid",
          "options": {
            "required": true,
            "foreign_key": true,
            "references_table": "customers",
            "references_column": "id",
            "relation_type": "many-to-one",
            "on_delete": "cascade"
          }
        },
        {
          "name": "total",
          "type": "decimal",
          "options": {
            "required": true
          }
        }
      ]
    }
  ]
}
JSON
```

You can also upload a JSON file:

```bash
curl -X POST "http://localhost:4000/api/v1/import/json" \
  -H "Authorization: Bearer <token>" \
  -F "file=@schema.json"
```

The uploaded file must contain the table array itself:

```json
[
  {
    "name": "customers",
    "parent": "base",
    "schema": [
      {
        "name": "name",
        "type": "varchar",
        "options": {
          "required": true,
          "unique": true
        }
      }
    ]
  }
]
```

Each table requires `name`, `parent`, and `schema`. Each column requires `name` and `type`; `options` is optional. Supported option fields include:

| Option | Type | Description |
|---|---|---|
| `required` | boolean | Whether the column is required |
| `unique` | boolean | Whether values must be unique |
| `default` | any | Default column value |
| `foreign_key` | boolean | Whether this column is a foreign key |
| `references_table` | string or null | Referenced table name |
| `references_column` | string or null | Referenced column; defaults to `id` for a foreign key |
| `relation_type` | string or null | `many-to-one`, `one-to-many`, `many-to-many`, or `one-to-one` |
| `through_table` | string or null | Join table for a many-to-many relation |
| `on_delete` | string or null | Delete behavior; defaults to `cascade` for a foreign key |
| `relation_name` | string or null | Explicit relation identifier |
| `inverse_relation` | string or null | Explicit inverse relation identifier |

The importer automatically orders JSON tables so referenced tables are created first.

Successful response:

```json
{
  "data": [
    {
      "table": "customers",
      "message": "table imported",
      "error": false
    },
    {
      "table": "orders",
      "message": "table imported",
      "error": false
    }
  ]
}
```

To retrieve the exact validation contract used by the running server:

```bash
curl "http://localhost:4000/api/v1/import/json" \
  -H "Authorization: Bearer <token>"
```

### **Validation and Errors**

Before DBML and JSON tables are created, the importer checks table and relation identifiers and verifies that referenced tables either already exist or are included in the import.

| Status | Meaning |
|---|---|
| `200` | The import request was accepted; inspect each result's `error` field where present |
| `401` / `403` | Authentication or authorization failed |
| `409` | A table/relation identifier already exists, or a referenced table is missing |
| `422` | SQL, DBML, or JSON could not be parsed or validated |

Missing reference response:

```json
{
  "error": "Some referenced tables do not exist",
  "missing_references": ["customers"]
}
```

Identifier conflict response:

```json
{
  "error": "Some identifiers are already taken",
  "conflicts": ["customers"]
}
```

Invalid JSON response:

```json
{
  "error": "JSON does not comply with the import schema",
  "validation_errors": [
    {
      "message": "Required property parent was not present.",
      "path": "#/0"
    }
  ]
}
```
